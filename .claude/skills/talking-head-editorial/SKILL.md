# Talking-Head Editorial

คลิปพูดหน้ากล้องที่ดูเหมือนตัดโดยบรรณาธิการภาพ: ซับขึ้นตามเสียงทีละคำ โดยในแต่ละก้อนมี **คำสำคัญคำเดียวตัวใหญ่**
แล้วตัดไปการ์ดเต็มจอสั้น ๆ ที่ "เล่า" ประโยคนั้น เช่น คำค่อย ๆ ประกอบกันบนการ์ดขาว, โปสเตอร์, B-roll หรือ motion graphics แล้วตัดกลับมาที่หน้าคนพูด.
สไตล์นี้คือฝั่ง "edited" ของงานรับตัดต่อแนว raw vs edited — ไม่ใส่กรอบเทียบ raw/edited, ปุ่ม "DM me" หรือจอท้าย TikTok.

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ.
คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป ส่วนเอนจิน, ชุดการ์ด, motion graphics, เสียง และ pipeline มีให้แล้ว.

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา. ข้อความบนจอใช้ตามบทของผู้ใช้เสมอ (แก้ได้แค่คำผิดชัด ๆ และบอกผู้ใช้).
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจงานด้วย preview / contact sheet เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นของ motion และเสียงต้องให้เขายืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** ผ่าน Claude Code บนเว็บ/แอป — เครื่องคลาวด์มี ffmpeg, Node + playwright, python3 แล้ว.
  ห้ามขอให้ผู้ใช้ติดตั้งหรือรันคำสั่งเอง. รัน `scripts/check_env.sh` ก่อนเสมอ.
- ไฟล์ที่ส่งในแชทต้อง ≤ ~30 MB (pipeline เข้ารหัสให้แล้ว); ไฟล์คุณภาพสูงส่งผ่าน GitHub (ขั้น 9).
- **ห้ามเกรดสีฟุตเทจ** — ผู้ใช้สั่งไว้: ไม่ใส่ filter สี / vignette / grain ใด ๆ บนวิดีโอคนพูด.
- **ฟอนต์ Mitr + Sriracha เท่านั้น** (ผู้ใช้เลือก) และ **ไม่ใส่บาร์โค้ด** บนการ์ดโปสเตอร์ — ผู้ใช้ไม่เอา.
- **ทำรวดเดียวจนได้คลิป** — ผู้ใช้ส่งคลิป + บทพูดแล้วรอรับ `edit.mp4` เท่านั้น: **ไม่ส่งแผนให้อนุมัติ ไม่ส่งภาพตัวอย่างให้อนุมัติ ไม่หยุดถามระหว่างทาง**
  (ถามได้เฉพาะเมื่อทำต่อไม่ได้จริง ๆ เช่น บทพูดไม่ครบความยาวคลิป หรือโหลดคลิปไม่ได้). วางแผนและตรวจภาพตัวอย่างเอง แล้วทำต่อทันที.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (เช่นใน scratchpad, ชื่อสั้นไม่มีช่องว่าง).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อน>` → `$P/input.*`
   (แนบได้ ~30 MB, ใหญ่กว่านั้นใช้ลิงก์ Drive แบบ "ทุกคนที่มีลิงก์" หรือแบ่งท่อน).
   **B-roll ที่ผู้ใช้ส่งมา:** รูปนิ่ง → คัดลอกไป `$P/img/` (ตั้งชื่อสั้น เช่น `i01.jpg`) แล้วใช้ `pic()`;
   คลิปวิดีโอ/ลิงก์ → `bash $SK/scripts/prep_broll.sh $P <ไฟล์|ลิงก์> <ชื่อ> [เริ่มวินาที] [ความยาว]` แล้วใช้ `clip()`.
   ดูรูปทุกรูปก่อนวางแผน (เนื้อหา, สีพื้นหลัง, ตำแหน่งคน) — รูปพื้นดำวางบนการ์ดดำ, รูปอื่นวางเป็นโปสเตอร์บนการ์ดครีม.
   **ถ้าผู้ใช้ไม่ได้ส่ง B-roll → ใช้ motion graphics** (`references/card-library.md` หัวข้อ MG) — ห้ามดึงรูปจากเน็ต.
   แบรนด์: ถ้าผู้ใช้มีสี/ฟอนต์ ให้คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้.
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทของผู้ใช้ — แม่นกว่าเวลาวินาทีเต็มมาก; ถ้าติดตั้ง/โหลดโมเดลไม่ได้ สคริปต์ถอยไปใช้
   `make_timeline.py` ให้เอง). แถวที่มี `*` คือเดาเวลาจากแถวข้าง ๆ — เปิด `words.json` ดูคำแถวนั้นแล้วแก้ใน chunks.json เองถ้าจำเป็น.
   ถ้าคำสุดท้ายของคลิปพูดจบชิดท้ายไฟล์ ให้ค้างภาพท้ายด้วย `HOLD=1.0` ตอนขั้น frames (การ์ดปิดท้ายจะอ่านทัน).
4. **ดูหน้าคนพูด** — `[HOLD=1.0] bash $SK/scripts/pipeline.sh $P <video> frames` แล้วเปิด `$P/grid.jpg` (เฟรมที่มีเส้นกริดทุก 100 px)
   เพื่อหาคาง/อก/มือ — ซับ A-roll วางที่ระดับอก (ค่าเริ่ม top 1150) ต้องไม่ทับหน้า.
5. **วางแผน (ทำเอง ไม่ต้องรอใคร)** — ตาราง `ช่วงเวลา · คำพูด · การจัดการ (ซับ A-roll / ชนิดการ์ด / ภาพหรือ MG)`;
   ช่อง MG บอกเป็นภาพที่เห็นซึ่งคิดจากประโยคนั้นของคลิปนี้ (ไม่ใช่ชื่อสูตรจากตัวอย่าง).
   หลักวางแผนดูหัวข้อ "จังหวะ" ด้านล่าง. แล้วทำข้อ 6 ต่อทันที.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` และ `references/card-library.md` ก่อน;
   เปิด `examples/timeline_mg.js` (ไม่มี B-roll, ใช้ MG) หรือ `examples/timeline_broll.js` (ใช้รูปผู้ใช้) เพื่อดูระดับงาน
   และวิธีใช้ฟังก์ชัน — **ออกแบบการ์ดและ MG ใหม่ให้คลิปนี้ทุกครั้ง** ห้ามคัดลอกการ์ดจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนคำ
   (ดู "Motion graphics ต้องทำใหม่ให้คลิปนั้น" ด้านล่าง). สไตล์ทั้งหมดยังเหมือนเดิม.
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อซับและต่อการ์ด
   (เวลาหลังคำสำคัญขึ้น ~0.3 วินาที). เปิด `$P/prev.jpg` ตรวจตาม QC ใน `references/standards.md` แก้จนผ่าน.
   render.js ออกด้วย exit code 2 ถ้ามี JavaScript error — แก้ก่อนไปต่อ.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (รัน background ได้; ~45 วินาทีใช้ ~5–8 นาที).
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg`, ส่ง `$P/edit.mp4` พร้อมตารางสรุปสิ่งที่ใส่แต่ละช่วง และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง** — ส่งทุกครั้งเมื่อ session มี GitHub repo: `pipeline.sh $P <video> hq` แล้วรันในโฟลเดอร์ repo
   `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อคลิป>_hq.mp4` → ส่งลิงก์ `DOWNLOAD:` พร้อมบอกว่า
   "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง" (branch `exports` เก็บเฉพาะไฟล์ล่าสุด).
   แก้ตามฟีดแบ็กเฉพาะจุด → preview จุดนั้น → เรนเดอร์ใหม่เป็น edit_v2.mp4, …

## จังหวะ (หัวใจของสไตล์)

- **ซับ A-roll ทุกก้อน = คำนำเล็ก + คำสำคัญคำเดียวตัวใหญ่.** คำนำขึ้นทีละวลีตามเสียง, คำสำคัญเด้งเข้า (เบลอ→คม, ย่อ 1.16→1).
  สลับคำสำคัญระหว่าง **ตัวหนา Mitr** (`k`) กับ **ลายมือ Sriracha** (`i`) ให้มีจังหวะ; ไฮไลต์กล่องสี (`hl`) ใช้กับคำที่เป็น "การกระทำ/ตัวปัญหา".
- **สี accent สีเดียวทั้งคลิป** (ค่าเริ่มเขียวมะนาว) — ที่เหลือขาว / กรมท่า / ครีม / ดำ. แดง `#FF3B30` ใช้ได้เฉพาะความหมายลบ (กราฟร่วง, กากบาท).
- **การ์ดเต็มจอทุก 2–4 วินาที รวม ~40–55% ของคลิป**, แต่ละการ์ดยาว 0.6–3 วินาที, เข้า-ออกแบบตัดชน (hard cut) —
  ความเคลื่อนไหวอยู่ในการ์ด ไม่ใช่ทรานสิชัน. การ์ดติดกันได้ไม่เกิน 3 ใบ แล้วต้องกลับมาหน้าคนพูด.
- **สลับชนิดการ์ด** ไม่ให้ซ้ำติดกัน: ขาว (คำประกอบทีละคำ) · ดำ/กรมท่า (คำ + สีไล่) · โปสเตอร์ครีม · ภาพ/MG บนพื้นดำ · `frame()` ย่อหน้าคนพูด (ใช้ 1 ครั้งต่อคลิป).
- **ซูมตัดชน** (punch-in 1.06–1.14 ทันที) ที่คำสำคัญบน A-roll แล้วกลับ 1.0 ที่ก้อนถัดไป — ไม่ซูมแบบไหลช้า.
- **Motion graphics ต้องทำใหม่ให้คลิปนั้น** (ผู้ใช้สั่ง) — การ์ดและ MG ทุกใบคิดจากเนื้อหาของคลิปนี้: ประโยคนี้พูดถึงอะไร
  ของ/การกระทำอะไรที่เห็นแล้วเข้าใจทันที และเหตุการณ์อะไรเกิดตรงคำสำคัญ — แล้วประกอบจากชิ้นใน kit. **ห้ามเอาการ์ดจากตัวอย่าง
  หรือคลิปก่อนมาเปลี่ยนคำพูด**; สองคลิปที่พูดเรื่องคล้ายกันก็ต้องได้ภาพที่คิดจากประโยคของคลิปนั้น.
  **สไตล์ไม่เปลี่ยน** — ภาษาภาพ Flat × Glow, ฟอนต์, accent สีเดียว, ชนิดการ์ด, การเคลื่อนไหว และกฎทั้งหมดในไฟล์นี้คงเดิม;
  ที่ต่างกันในแต่ละคลิปคือ "วาดอะไร จัดวางยังไง และอะไรเกิดตรงคำ".
- **ห้ามแต่งข้อเท็จจริง** — ไม่ใส่ตัวเลข ราคา ชื่อ หรือข้อมูลที่ผู้พูดไม่ได้พูด; ข้อความใน MG (ปุ่ม, ป้าย) ใช้คำจากบทหรือคำ UI กลาง ๆ
  เช่น "ชำระเงิน"; ไม่ใช้โลโก้แบรนด์จริง.
- **ไม่บังหน้า** — ซับ A-roll อยู่ระดับอก, เว้นล่าง 300 px และขวา 140 px ให้ UI ของแพลตฟอร์ม.
