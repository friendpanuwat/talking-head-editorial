# Talking-Head Editorial · Overlay

สไตล์นี้แตกจาก `talking-head-editorial`:
ใช้ซับ, ฟอนต์, สี, เสียง และ pipeline ชุดเดียวกับ editorial แต่ **ไม่มีการ์ดเต็มจอ** — หน้าคนพูดชัดตลอดทั้งคลิป
และภาพประกอบเป็น **วิดเจ็ตเล็ก** สไตล์การ์ดแบน (แบน มุมมน เด้งแบบสปริง) ที่เด้งขึ้นในที่ว่างของเฟรม (ปกติเหนือหัว)
เฉพาะตอนที่ประโยคนั้นมีภาพให้เล่า เช่น แชตที่ลูกค้าอ่านแล้วออฟไลน์, ป้ายราคา + ?, กราฟร่วง, ชิป "ส่วนลด" โดนกากบาท, ปุ่มชำระเงินที่เคอร์เซอร์ไม่กด, เป้าล็อกตรงกลาง.

งานนี้ทำด้วยโค้ด: HTML/CSS/WAAPI เรนเดอร์ทีละเฟรมใน Chromium (Playwright) แล้วรวมด้วย ffmpeg — ทุกเฟรมคำนวณจากเวลา จึงเรนเดอร์ซ้ำได้ตรงเป๊ะ.
คุณ (Claude) เป็นคนเขียน `timeline.js` ของแต่ละคลิป; เอนจิน, MG kit, วิดเจ็ต, เสียง และ pipeline มีให้แล้ว.
**ขั้นตอนใช้งานเหมือน talking-head-editorial ทุกอย่าง.**

## สิ่งที่ต้องรู้ก่อนเริ่ม

- **คุณฟังเสียงไม่ได้** → ต้องได้บทพูดพร้อมเวลาจากผู้ใช้ (.srt หรือบรรทัด `MM:SS ข้อความ`).
  ถ้าบทไม่ครบความยาวคลิป ให้ถามส่วนที่ขาด อย่าเดาเนื้อหา. ข้อความบนจอใช้ตามบทของผู้ใช้ (แก้ได้แค่คำผิดชัด ๆ และบอกผู้ใช้).
- **คุณดูวิดีโอได้แค่เป็นภาพนิ่ง** → ตรวจด้วย preview / crop โซนวิดเจ็ต / contact sheet เสมอ และบอกผู้ใช้ตรง ๆ ว่าความลื่นและเสียงต้องให้เขายืนยัน.
- **ผู้ใช้ส่วนใหญ่สั่งงานจากมือถือ** — เครื่องคลาวด์มี ffmpeg, Node + playwright, python3 แล้ว. ห้ามขอให้ผู้ใช้ติดตั้งหรือรันคำสั่งเอง.
  รัน `scripts/check_env.sh` ก่อนเสมอ.
- ไฟล์ที่ส่งในแชทต้อง ≤ ~30 MB; ไฟล์คุณภาพสูงส่งผ่าน GitHub (ขั้น 9).
- **ห้ามเกรดสี ห้ามเบลอ/หรี่คลิป** · **ฟอนต์ Mitr + Sriracha เท่านั้น** · **ไม่ใส่บาร์โค้ด** — ผู้ใช้กำหนดไว้.
- **ทำรวดเดียวจนได้คลิป** — ผู้ใช้ส่งคลิป + บทพูดแล้วรอรับ `edit.mp4` เท่านั้น: **ไม่ส่งแผนให้อนุมัติ ไม่ส่งภาพตัวอย่างให้อนุมัติ ไม่หยุดถามระหว่างทาง**
  (ถามได้เฉพาะเมื่อทำต่อไม่ได้จริง ๆ เช่น บทพูดไม่ครบความยาวคลิป หรือโหลดคลิปไม่ได้). วางแผนและตรวจภาพตัวอย่างเอง แล้วทำต่อทันที.

## Workflow

ตั้ง `SK=<path ของ skill นี้>` และ `P=<โฟลเดอร์งาน>` (ชื่อสั้นไม่มีช่องว่าง, ใน scratchpad).

1. **ตรวจเครื่อง** — `bash $SK/scripts/check_env.sh`
2. **รับไฟล์** — `bash $SK/scripts/fetch_video.sh $P <ไฟล์แนบ | ลิงก์ Google Drive | หลายท่อน>` → `$P/input.*`
   (แนบได้ ~30 MB, ใหญ่กว่านั้นใช้ลิงก์ Drive แบบ "ทุกคนที่มีลิงก์" หรือแบ่งท่อน). แบรนด์: คัดลอก `$SK/assets/brand.default.json` เป็น `$P/brand.json` แล้วแก้ถ้าผู้ใช้มีสี.
   รูปที่ผู้ใช้ส่งมาใช้เป็น **ภาพเล็กในวิดเจ็ต** ได้ (`pic(w, 'img/x.jpg', t, css)` ในกล่อง widget) — ไม่ขยายเต็มจอ.
3. **จับเวลาบทพูด** — `bash $SK/scripts/word_timing.sh $P <video> <transcript>` → `chunks.json` / `chunks.md`
   (Whisper จับเวลาจริงทีละคำแล้วจับคู่กับบทผู้ใช้; ถ้าใช้ไม่ได้จะถอยไป `make_timeline.py` เอง). แถว `*` = เดาเวลา ให้ตรวจใน `words.json`.
   ถ้าคำสุดท้ายพูดชิดท้ายไฟล์ ใช้ `HOLD=1.0` ตอนขั้น frames.
4. **หาโซนวิดเจ็ต** — `[HOLD=1.0] bash $SK/scripts/pipeline.sh $P <video> frames` แล้วเปิด `$P/grid.jpg` (เส้นกริดทุก 100 px)
   + contact sheet ทุก 2 วินาที: `ffmpeg -pattern_type glob -i "$P/src_frames/*.jpg" -vf "select='not(mod(n\,60))',scale=270:480,tile=7x3" -frames:v 1 $P/contact.jpg`.
   โซนวิดเจ็ต = เหนือหัว y ≈ 130 → (ยอดหัวสูงสุด − 40 px) (ซูม 1.1 ดันหัวขึ้น ~30 px). ถ้าเหนือหัวแคบกว่า ~250 px ใช้ข้างลำตัวแทนและย่อวิดเจ็ต.
   ซับอยู่ระดับอก (ค่าเริ่ม top 1150) — ต้องไม่ทับปาก.
5. **วางแผน (ทำเอง ไม่ต้องรอใคร)** — ตาราง `ช่วงเวลา · คำพูด · ซับ (คำใหญ่) · วิดเจ็ต` (บอกวิดเจ็ตเป็นภาพที่เห็น ซึ่งคิดจากประโยคนั้นของคลิปนี้). วิดเจ็ต ~1 ชิ้นต่อ 3 วินาที
   (≈ 12–14 ชิ้นต่อ 40 วินาที) เฉพาะประโยคที่ภาพช่วยเล่า + เว้นช่องว่างไม่มีวิดเจ็ต 3–5 ช่องให้พักสายตา. แล้วทำข้อ 6 ต่อทันที.
6. **เขียน `$P/timeline.js`** — อ่าน `references/timeline-api.md` และ `references/widget-library.md` ก่อน;
   เปิด `examples/timeline_example.js` (ของจริง 42 วินาที, 14 วิดเจ็ต) เพื่อดูระดับงานและวิธีใช้ฟังก์ชัน —
   **ออกแบบวิดเจ็ตใหม่ให้คลิปนี้ทุกครั้ง** ห้ามคัดลอกบล็อกวิดเจ็ตจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนเวลา/ข้อความ/ไอคอน
   (ดู "วิดเจ็ตต้องทำใหม่ให้คลิปนั้น" ด้านล่าง). สไตล์ทั้งหมดยังเหมือนเดิม.
   **ห้ามเรียก `cards()` / `card()` / `frame()` / `mood()`** และห้าม `backdrop-filter` / `bg:'glass'` (สไตล์นี้คลิปต้องคมและเห็นหน้าตลอด).
7. **Build + preview + ตรวจเอง** — `bash $SK/scripts/pipeline.sh $P <video> build` แล้ว
   `PREVIEW="t1,t2,..." bash $SK/scripts/pipeline.sh $P <video> preview` อย่างน้อย 1 เฟรมต่อวิดเจ็ตและต่อซับ (หลังขึ้น ~0.4 วิ).
   ซูมดูโซนวิดเจ็ต: `ffmpeg -pattern_type glob -i "$P/prev/p_*.jpg" -vf "crop=1080:600:0:100,scale=540:-2,tile=3x4" -frames:v 1 $P/top.jpg`.
   แก้ตาม QC ใน `references/standards.md`. เอนจินโยน error (render.js exit 2) ถ้าวิดเจ็ตซ้อนเวลากัน.
8. **เรนเดอร์ + เสียง + ไฟล์** — `pipeline.sh $P <video> render`, `... audio`, `... encode` (background ได้; ~45 วิ ใช้ ~5–8 นาที).
   ระหว่างเรนเดอร์อย่าแก้ไฟล์ใน `scripts/` (bash อ่านสคริปต์ทีละส่วน — แก้กลางทางทำให้ขั้นถัดไปพัง).
9. **QC รอบสุดท้ายแล้วส่ง** — ดู `$P/qc_sheet.jpg`, ส่ง `$P/edit.mp4` + ตาราง "วินาที · วิดเจ็ต" และขอฟีดแบ็กแบบระบุวินาที.
   **ไฟล์คุณภาพสูง** — ส่งทุกครั้งเมื่อ session มี GitHub repo (ไม่ต้องรอให้ผู้ใช้ขอ): `pipeline.sh $P <video> hq` แล้วรันในโฟลเดอร์ repo
   `bash $SK/scripts/deliver_github.sh $P/edit_hq.mp4 <ชื่อคลิป>_hq.mp4` → ส่งลิงก์ `DOWNLOAD:` พร้อมบอกว่า
   "เปิดลิงก์ในเบราว์เซอร์ที่ล็อกอิน GitHub แล้ว ไฟล์จะดาวน์โหลดลงเครื่อง" (branch `exports` เก็บเฉพาะไฟล์ล่าสุด).
   แก้ตามฟีดแบ็กเฉพาะจุด → preview จุดนั้น → เรนเดอร์ใหม่เป็น edit_v2.mp4, …

## หลักที่ทำให้สไตล์นี้ออกมาดี

- **หน้าคนพูดคือพระเอก** — วิดเจ็ตเป็น "คำอธิบายภาพ" ข้างหัว: เล็ก (≤ ~600×380), ไม่บังหน้าแม้ตอนซูม, ทีละชิ้น.
- **ซับครบทุกคำพูด** — ไม่มีการ์ดมาช่วยเล่า; ทุกก้อน = คำนำเล็ก + คำใหญ่คำเดียว (สลับ `k` Mitr / `i` Sriracha / `hl` กล่องไฮไลต์).
  ประโยค "ไม่ใช่ X" ใช้ `strike()` บนคำในซับได้เลย.
- **ซูมตัดชน** 1.05–1.10 ที่คำใหญ่ แล้วกลับ 1.0 ที่ก้อนถัดไป (editorial) — วิดเจ็ตและซับไม่ซูมตามกล้อง.
- **วิดเจ็ตต้องทำใหม่ให้คลิปนั้น** (ผู้ใช้สั่ง) — คิดจากเนื้อหาของคลิปนี้ทีละประโยค: พูดถึงอะไร, เห็นอะไรแล้วเข้าใจทันที,
  อะไรเกิดตรงคำสำคัญ — แล้วประกอบจากชิ้นใน kit. **ห้ามเอาวิดเจ็ตจากตัวอย่างหรือคลิปก่อนมาเปลี่ยนเวลา/ข้อความ/ไอคอน**.
  **สไตล์ไม่เปลี่ยน** — การ์ดแบน การ์ดขาว ไอคอนเส้น accent สีเดียว ขนาด โซน และการเคลื่อนไหวคงเดิม;
  ที่ต่างกันในแต่ละคลิปคือ "วาดอะไร จัดวางยังไง และอะไรเกิดตรงคำ".
- **วิดเจ็ตต้องเล่าความหมาย** และมี "เหตุการณ์ตรงคำ" อย่างน้อย 1 อย่าง (เด้งย้ำ, ส่าย, กากบาท, กราฟร่วง, ลูกศรเข้าเป้า).
  ส่วนประกอบในวิดเจ็ตขึ้นตามคำพูด (แถวที่ 2 ขึ้นตอนพูดข้อที่ 2).
- **สี:** accent สีเดียว + ขาว + กรมท่า; แดง `#FF3B30` เฉพาะความหมายลบ (กราฟร่วง, กากบาท). ข้อความในวิดเจ็ตสั้น ≤ 3 คำ.
- **ห้ามแต่งข้อเท็จจริง** — ไม่ใส่ตัวเลข ราคา % ชื่อ ที่ผู้พูดไม่ได้พูด (กราฟใช้สัดส่วนไม่มีตัวเลข); ป้าย UI กลาง ๆ ใช้ได้ ("ลูกค้า", "ออนไลน์", "ชำระเงิน"); ไม่ใช้โลโก้จริง.
- **นิ่งดีกว่าจุกจิก** — ไม่ใช้กลิตช์, อีโมจิ, เสียงการ์ตูน.

## ไฟล์ใน skill

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `references/timeline-api.md` | ก่อนเขียน timeline.js — ซับ ซูม เสียง วิดเจ็ต และ MG kit |
| `references/widget-library.md` | วิธีออกแบบวิดเจ็ตใหม่ให้คลิป + ตัวอย่างวิธีคิด 14 แบบจากคลิปตัวอย่าง |
| `references/standards.md` | ฟอนต์ สี โซน motion เสียง QC และแบรนด์ |
| `examples/timeline_example.js` | ตัวอย่างระดับงานเต็มคลิป (ไทย 42 วินาที, 14 วิดเจ็ต) — ดูเป็นไอเดีย ห้ามคัดลอกวิดเจ็ต |
| `scripts/word_timing.sh` | บท + เสียง → chunks.json เวลาระดับคำ (Whisper, มี fallback) |
| `scripts/pipeline.sh` | frames · build · preview · render · audio · encode · hq (`HOLD=` ค้างภาพท้าย) |
| `scripts/mix_sfx.sh` | วางเสียงประกอบใต้เสียงพูด และหรี่ลงตอนคนพูด (pipeline เรียกเอง — กติกาเดียวกันทุกสกิล) |
| `scripts/fetch_video.sh` · `deliver_github.sh` | รับคลิป · ส่งไฟล์คุณภาพสูง |
| `assets/engine_*.html` | เอนจิน + MG kit + widget (ไม่ต้องแก้) |
| `assets/brand.default.json` | ค่าแบรนด์เริ่มต้น (accent เขียวมะนาว, Mitr + Sriracha) |
